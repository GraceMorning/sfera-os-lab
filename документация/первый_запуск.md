# Первый запуск

## Что доказывает этот этап

После сборки получается ровно один загрузочный сектор размером 512 байт.
Компьютерная прошивка может распознать его по подписи `55 aa` и передать ему
управление.

Загрузчик не использует Linux, macOS или другую готовую операционную систему
во время работы. Он напрямую настраивает последовательный порт и отправляет
текст в QEMU.

## Почему сейчас есть ассемблер

Компилятор «Сферы» уже умеет создавать нативный код для обычной среды, но
цель без операционной системы требует дополнительных соглашений:

1. какая функция является точкой входа;
2. кто настраивает стек;
3. кто отвечает за память;
4. какой формат имеет загрузочный образ;
5. как передаются данные от загрузчика к ядру;
6. какие функции стандартной библиотеки доступны без операционной системы.

Маленький ассемблерный загрузчик временно фиксирует эти границы. Это не
замена Сфере и не конечная архитектура. Следующая задача — добавить такие
соглашения в компилятор и заменить вывод загрузчика на вызов функции из
`ядро/главная.код`.

## Проверка образа

Команда `сборка/собрать.sh` проверяет две вещи:

- размер результата равен 512 байтам;
- последние два байта образа равны `55 aa`.

Если одна из проверок не проходит, образ не считается готовым к запуску.

Команда `сборка/проверить_запуск.sh` выполняет следующий уровень проверки:

- запускает собранный образ в QEMU;
- подключает последовательный порт к временному файлу;
- даёт загрузчику выполниться и завершает QEMU;
- проверяет сообщение `Сфера ОС Лаб: загрузчик работает!` после сброса
  последовательного вывода.

Так мы проверяем не только формат образа, но и фактическое выполнение
загрузчика.
